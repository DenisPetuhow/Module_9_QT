Ключевой момент: почему передаём QList, а не QSqlQuery
НЕЛЬЗЯ — QSqlQuery между потоками:

  Рабочий поток:
    QSqlQuery query(__db);
    query.exec("SELECT ...");
    emit sig_ready(query);   // передаём в главный поток
                             //   ↓
  Главный поток:             //   ↓
    query.next();            // ← ОБРАЩЕНИЕ к __db из чужого потока!
                             //   QSqlDatabase живёт в рабочем потоке
                             //   → crash или повреждение данных


ПРАВИЛЬНО — извлекаем данные и передаём копию:

  Рабочий поток:
    QSqlQuery query(__db);
    query.exec("SELECT ...");
    QList<QPair<...>> list;
    while (query.next())
      list.append(...);      // ← извлекли ВСЕ данные здесь
    emit sig_ready(list);    // передаём простую структуру
                             //   ↓
  Главный поток:             //   ↓
    for (auto &pair : list)  // ← работаем с КОПИЕЙ, БД не трогаем
      cb->addItem(...);      //   безопасно!

QPair — это просто пара значений
Представь, что тебе нужно хранить вместе две связанные вещи: название аэропорта и его код. Можно создать структуру:
cpp// Вариант 1: своя структура
struct Airport {
    QString name;   // "Шереметьево"
    QString code;   // "SVO"
};
QPair — это готовая структура от Qt, которая делает то же самое, но универсально, без объявления нового типа:
cpp// Вариант 2: QPair — та же пара, но без объявления структуры
QPair<QString, QString> airport;
airport.first  = "Шереметьево";   // первый элемент пары
airport.second = "SVO";            // второй элемент пары

// Или короче через функцию-помощник:
auto airport = qMakePair(QString("Шереметьево"), QString("SVO"));
По сути QPair<A, B> внутри — это просто:
cpptemplate <typename T1, typename T2>
struct QPair {
    T1 first;    // первое значение
    T2 second;   // второе значение
};
QList — это динамический массив
Аналог std::vector. Хранит последовательность элементов, может расти:
cppQList<QString> cities;
cities.append("Москва");       // индекс 0
cities.append("Петербург");    // индекс 1
cities.append("Новосибирск");  // индекс 2

cities[0];          // → "Москва"
cities.size();      // → 3
QList + QPair вместе
Когда соединяем — получаем список пар:
cppQList<QPair<QString, QString>> airports;

//                    first           second
//                    (название)      (код)
airports.append(qMakePair(QString("Абакан"),       QString("ABA")));
airports.append(qMakePair(QString("Шереметьево"),  QString("SVO")));
airports.append(qMakePair(QString("Внуково"),      QString("VKO")));
В памяти это выглядит так:
airports (QList)

Как мы используем это в проекте
В Database (рабочий поток) — заполняем список из результата SQL-запроса:
cppQList<QPair<QString, QString>> airports;

while (query.next()) {
    QString name = query.value(0).toString();   // "Шереметьево"
    QString code = query.value(1).toString();   // "SVO"
    airports.append(qMakePair(name, code));     // добавляем пару в список
}

emit sig_airportsReady(airports);   // отправляем КОПИЮ списка в MainWindow
В MainWindow (главный поток) — читаем список и заполняем QComboBox:
cppvoid MainWindow::onAirportsReady(QList<QPair<QString, QString>> airports)
{
    for (const auto &pair : airports) {
        // pair.first  → "Шереметьево"  (видит пользователь)
        // pair.second → "SVO"           (скрытые данные для SQL)
        ui->cb_airport->addItem(pair.first, pair.second);
    }
}
Альтернативы — когда что использовать
Нужно хранить пару значений:
  QPair<QString, QString>     ← наш случай, быстро и просто

Нужно хранить 3+ полей:
  struct Airport {            ← своя структура понятнее
      QString name;
      QString code;
      QString city;
  };

Нужно искать по ключу (код → название):
  QMap<QString, QString>      ← словарь, поиск за O(log n)
Мы выбрали QPair потому что у нас ровно два поля и данные просто перекладываются из SQL в ComboBox — поиск по ключу не нужен.
