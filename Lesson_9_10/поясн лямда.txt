Отличный вопрос! Лямбда-выражения (или просто «лямбды») — это, по сути, безымянные мини-функции, которые мы пишем прямо внутри другой функции.

То, что находится в квадратных скобках [], называется списком захвата (capture list). Это «рюкзак», в который лямбда кладет всё необходимое из внешнего мира, чтобы выполнить свою работу.

Давай разберем подробно, почему там написано [&] или [this] и что будет, если это поменять.

1. Почему лямбда «слепая»?
Представь, что лямбда — это маленькая комната без окон.

C++
// Пустая лямбда
[] {
    DisplayConnectStatus(10); // ОШИБКА!
};
Эта лямбда не видит ничего, что находится снаружи её фигурных скобок {}. Она не знает, что такое DisplayConnectStatus. Она не знает, что она находится внутри класса MainWindow.

Чтобы она увидела методы вашего класса, ей нужно дать «пропуск». Этим пропуском и являются квадратные скобки [].

2. Что значат разные символы в []?
Вот самые частые варианты, которые можно написать внутри скобок:

А. [this] — "Мне нужен доступ к текущему объекту"
Это самый правильный вариант для твоего случая.

C++
connect(__client, &TCPclient::sig_Disconnected, this, [this]{
    // Теперь я вижу всё, что есть в классе MainWindow!
    this->DisplayConnectStatus(ERR_CONNECT_TO_HOST); 
});
Как это работает: Лямбда захватывает указатель this. Благодаря этому она может вызывать методы класса (DisplayConnectStatus, ui->...) и трогать переменные класса.

Когда использовать: Когда внутри лямбды нужно вызвать функцию этого же класса или обновить GUI.

Б. [&] — "Мне нужен доступ ко ВСЕМУ по ССЫЛКЕ"
Это то, что было в твоем примере.

C++
connect(..., [&]{ 
    DisplayConnectStatus(...); 
});
Как это работает: Лямбда автоматически захватывает всё, что видит вокруг (и this, и локальные переменные метода), по ссылке.

Плюс: Не надо думать, что конкретно захватить.

Минус: Это опасно для локальных переменных (которые исчезают при выходе из функции), но для this (методов класса) это безопасно и работает так же, как [this].

В. [=] — "Сделай мне КОПИИ всего"
C++
connect(..., [=]{ 
    int a = some_local_var; // a - это копия
    DisplayConnectStatus(...); // Работает, так как this копируется как указатель
});
Как это работает: Лямбда делает копии всех локальных переменных.

Нюанс: Указатель this тоже копируется, поэтому методы класса всё равно доступны и работают с оригинальным объектом.

Г. [] — "Мне ничего не нужно"
C++
connect(..., []{ 
    qDebug() << "Просто сообщение в консоль"; // Работает
    // DisplayConnectStatus(...); // ОШИБКА! Не вижу этот метод
});
Когда использовать: Если лямбда делает чисто математические вычисления или выводит простой лог, не трогая сам класс MainWindow.

3. Ответ на твой вопрос: "Зачем this, он всегда?"
Нет, this нужен не всегда.

Он нужен только если внутри лямбды ты обращаешься к "внутренностям" своего класса:

Вызываешь методы (как DisplayConnectStatus).

Трогаешь интерфейс (ui->label->setText...).

Меняешь переменные класса (__counterPck++).

Если ты напишешь лямбду без this (просто []), компилятор выдаст ошибку вроде:

'this' was not captured for this lambda function (Я не знаю, чей метод DisplayConnectStatus вызывать, дай мне объект!)

Пример из жизни
Представь, что MainWindow — это Дом. DisplayConnectStatus — это Телевизор в доме. Лямбда — это Гость.

Если ты пустишь гостя в дом ([this]), он сможет включить телевизор.

Если ты оставишь гостя на улице ([]), он не сможет включить телевизор, потому что у него нет доступа к дому.

Итог для твоего кода
В строке:

C++
connect(__client, &TCPclient::sig_Disconnected, this, [&]{
    DisplayConnectStatus(ERR_CONNECT_TO_HOST);
});
Ты использовал [&]. Это сработало, потому что [&] автоматически захватил this, позволив лямбде "увидеть" и вызвать метод DisplayConnectStatus.

Если бы ты написал [], код бы не скомпилировался. Лучшей практикой считается писать [this], чтобы явно показать: "Эта функция работает с текущим объектом".
